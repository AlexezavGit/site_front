## ⚠️ Нереалізовано — велика хвиля вимог (сесія 2026-07-06)

### 1. Три тейлор-мейд лендінги замість спільного шаблону
- Ідеально: 3 окремі сторінки-входи (Provider/Beneficiary/Donor), кожна зі своїм "сленгом", акцентами й аргументами під конкретну аудиторію.
- Альтернатива: одна сторінка з сортуючими питаннями → редірект на тейлор-мейд сторінку групи.
- Крос-посилання між лендінгами (якщо хтось "заблукав" перед реєстрацією).
- Контент беремо з репо **Front** (`https://replit.com/@alexezav/Front`) — там є 3 кабінети з інтерактивними калькуляторами; якщо валідні — переносимо їхній контент як контент 3-х лендінгів, комбінуючи з поточним Home.tsx.
- Кнопка реєстрації — всюди зверху, окрім дашборду (окрема система).
- Перед реєстрацією повинен бути вибір: **публічний контроль** (без реєстрації) або **сайт про програму** (feelagain.me) або **дашборд з даними**.

### 2. Інфографіка "шлях користувача" (3 паралельні вертикальні доріжки)
- 3 вертикальні доріжки (Provider / Beneficiary / Donor), що перетинаються горизонтально через тригери: смарт-контракт, транзакції, протокол надання спеціалізованої психологічної допомоги.
- Логіка "зворотного водоспаду" ресурсів: громада → діагностика → сеанси → зворотний зв'язок.
- Частини цієї діаграми мають потім "осісти" всередині відповідних кабінетів (не лишатись тільки на лендінгу).

### 3. Перерозподіл існуючих сторінок Monitoring/Transparency/Reports по кабінетах
Це НЕ спільна сторінка. Розподіл:
- **ProviderCabinet** → формування звітів (генерація, а не перегляд).
- **DonorCabinet** → перевірка звітності + запит зворотного зв'язку (сам зворотний зв'язок живе у BeneficiaryCabinet).
- **Supervisor / Публічний контроль** → сторінка Monitoring & Control (AI Modules, Blockchain Monitor, Anomalies) — зараз такої ролі/сторінки НЕМАЄ, треба створити з нуля.
- Джерело контенту: проєкт "front" (dashboard-стиль, зараз використовується як referнс) — секції "Impact Financing Hub" (додати 4 проєкти допомоги для балансу сторінки, виправити занадто темний текст в "Active Programs"), "AI Modules" (виправити темний текст), "Donations-віджет" (має бути всюди, показує що кошти йдуть напряму конкретному фахівцю на користь конкретного бенефіціара, з детальним звітом за транзакцією — повний розділ у DonorCabinet), "Transparency" (→ сторінка публічного контролю).

### 4. Provider Onboarding (не просто Compliance)
- P0-B в чергу задач треба переформулювати: будуємо повний онбординг провайдера, комплаєнс — це його частина, не окрема паралельна фіча.
- Онбординг включає: верифікацію диплому/сертифікату (ДІЯ), рівні 0→1→2→3, доступ до циркуляційного фолдера, підвищення кваліфікації з блокуванням періоду прийому бенефіціарів і розрахунком pro-bono годин.

### 5. Оновлені канонічні константи (потребують звірки з користувачем — див. Master-Context §5)
- `TRAINING_GROUP_COST`: було €48,025 → користувач тепер каже €90k. НЕ ЗАМІНЕНО автоматично — треба уточнити, чи це заміна, чи інша метрика.
- `PRO_BONO_HOURS_PER_STUDENT`: було 120 год фіксовано → тепер діапазон 120–140 год.

### 6. Контент з інших Replit-репо для розподілу по кабінетах (за проханням користувача "поділись що визначено до переносу")
Зі зробленого дослідження попередніх сесій (див. Master-Context §5 "GITHUB REPOS"):
- **DigitalBus / ServiceAdmin** — sidebar-навігація (Overview/Impact Financing Hub/Monitoring & Control/Donations/Transparency/Reports), live-metrics API патерн, donor journey (D1–D6), Replit Auth патерн (НЕ використовується зараз — окреме питання Q2 в Master-Context).
- **terminal repo** — `ImpactCalculator.tsx` (канонічні формули), `Charts.tsx`, `FlipNumber.tsx`, `lib/data.ts` (канонічний датасет транзакцій/клініцистів v1.0).
- **Unified Admin Panel** (`https://replit.com/@alexezav/Unified-admin-panel`) — логіка взаємодії провайдер↔бенефіціар (циркуляційний фолдер, запрошення, акцепт), і в ньому є готова реєстрація — розглянути перевикористання.
- **Front repo** (`https://replit.com/@alexezav/Front`) — НЕ ДОСЛІДЖЕНО ЩЕ в цій сесії; містить 3 кабінети з калькуляторами, призначені стати контентом 3-х лендінгів. **Наступний крок: відкрити і проаналізувати цей репо.**
- Існуючий AdminCabinet.tsx у поточному проєкті — має бути розформований, його функціонал переїжджає в Provider/Donor/Supervisor кабінети (адмінська роль як окрема сутність зникає).

### 7. Двомовність
- Весь новий контент — двомовний (укр. + англ.), українська — пріоритетна/дефолтна мова. Зараз проєкт має тільки українську (правило "100% українською" з Master-Context §12 п.7 — треба переглянути це правило, воно застаріло).

### 8. Загальний mobile-first стандарт (застосовується з цієї сесії)
Всі нові сторінки й секції — спочатку базові (мобільні) Tailwind-класи, потім `sm:`/`md:` розширення. Explicit `grid-cols-1 md:grid-cols-[...]`, зменшені паддінги на мобільних, перевірка переносу довгого тексту в декоративних блоках (border/plaque).
